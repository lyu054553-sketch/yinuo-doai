# 上服案例数据

由上服提供的 `shangfu-cases-workflow.docx` 整理而来，供原型、资源匹配、需求落实审计和视觉模型测试共用。

## 文件

| 文件 | 内容 | 用途 |
|---|---|---|
| `cases.json` | 6 个案例：客户原话、设计语言八个字段、原话逐句拆分及与字段的对应关系和状态 | 需求落实审计的标准答案；演示素材 |
| `resources.json` | 从案例提取的版型、肩型、领型、面料、纹样、色彩、衣长、工艺，以及 8 条“身形 → 版型处理”规则，每条注明来源案例 | 资源匹配的候选库；“有来源”推荐的出处 |
| `resources_sim.json` | **模拟资源库与模拟仓库**（演示数据）：补齐案例覆盖不到的常见版型、领型、面料、纹样、色彩、衣长、工艺，编号以 M 开头、来源记为 `sim`；另有 19 个模拟货号（SIM- 开头，含色号、库存米数、交期） | 方案匹配的补充候选；面料现货与交接单领料建议。落地时整份替换为上服真实数据，或设 `YINUO_SIM_LIBRARY=0` 关闭 |
| `images.json` | 15 张图片的领型、闭合方式、纽扣、衣长、廓形、纹样、颜色标注 | 视觉模型的测试答案 |
| `workflow.json` | 案例六从设计语言到成衣的 6 个环节，含每步的输出、核对项、CAD 裁片和工艺说明 | 规格护照原型；打样核对清单 |
| `images/` | 文档中的原图，按案例和类型重新命名 | 演示和测试 |

## 规则

- **案例五是留出测试案例。** 开发、写提示词示例、调规则时都不要用它，只在最后测试时使用。测试资源匹配时，要先排除只来自案例五的资源：`F7` 肌理提花针织、`P2` 徽派纹样、`CO2` 撞色。
- **资源都是“案例参考”，不是库存。** 演示中不能说成集团现有面料或货号。`resources_sim.json` 里的模拟库和模拟仓库是演示数据，界面和交接单都标“模拟”，同样不能说成上服库存。
- **上服的真实图片只做测试，不进视觉模型的训练数据。**
- **标注都需要人工复核。** 原话与字段的对应关系、图片标注均为 Claude 整理和目测，尚未经人工核对，更没有经过设计师确认。

## 状态统计（共 52 句原话，每句取最严重的状态）

| 状态 | 句数 | 主要例子 |
|---|---|---|
| 已落实 | 29 | “领子不能太高” → 低立领 3cm 以内 |
| 间接体现 | 17 | “适合正式场合” → 无场景字段，靠面料体现 |
| 需设计师判断 | 3 | 案例二“领子要窄”、案例四“溜肩”、案例六“身形偏高” |
| 有冲突 | 2 | 案例二“整体宽松”对“微微收腰”；案例三“腰部宽松”对“收腰大A摆” |
| 被改写 | 1 | 案例二“最好是梅花” → 植物暗花＋点状星光 |

## 整理中发现、需向上服确认的问题

1. 案例六打样样衣是白色无纹面料，而文档写“用选定的同款面料制作初样样衣”，可能是坯布样衣。
2. 案例三外套底色在挂拍图里目测偏银灰，规格写的是“米白底色”。
3. 案例二、案例三的冲突项，是客户后来接受了，还是转化时遗漏了。
4. 案例一的上身效果图带“豆包AI生成”水印，其他效果图是否也由 AI 生成。
