# 对照命题要求的逐条方案说明

项目：衣诺 · 海派定制需求解构与可视化 Agent
命题：FDE-03 海派定制服饰 AI 需求解构与可视化 Agent（命题方：上海服装集团）
日期：2026-11-24

命题条目按 DOAI 官网 FDE 赛道页面 FDE-03 的原文逐条列出（2026-11-24 核对）。每条写明衣诺怎么做、在原型哪里看、证据在哪，以及没做到或有限制的地方。

“在原型哪里看”指本机演示界面：左侧导航栏有「新建洽谈」「资源知识库」「最近洽谈」；每场洽谈分四步：① 核对需求 ② 和客户确认 ③ 方案 ④ 交接。证据文件都在本目录（`docs/交付/`）下。

状态说明：**已实现**＝原型里能现场演示；**部分实现**＝能演示，但范围或准确度有明确限制；**未做**＝本轮没有实现。

## 一、Agent 能力与输出物

### 1. 结构化定制资产知识库

> 归集海派经典版型、特色面料、非遗或经典工艺、高端定制与职业服历史案例，完成标签化、风格化、场景化分类，明确资源适配场景与使用规范。
> 输出物：可检索定制资产知识库、定制资源分类清单

| 项 | 内容 |
| --- | --- |
| 衣诺怎么做 | 从上服六个案例整理出资源库，按版型、肩型、领型、面料、工艺、纹样、色彩、长度、身形规则 9 类，另加历史案例。目录共 43 项，其中 40 项有开发集案例依据，可以进入推荐。每项带风格标签、场景标签、适配与使用规范、来源案例和分类依据；缺的元数据（如使用人群）标“未记录”，不补编。 |
| 在原型哪里看 | 左侧「资源知识库」：按关键词、资源类型、风格标签、场景标签筛选；可导出当前分类清单（CSV）。方案里引用的每个资源编号（如 S1、F3）都能在这里查到。 |
| 证据 | [定制资源分类清单 CSV](定制资源分类清单_20261119.csv)；接口 `GET /api/resource-catalog`；截图 [资源知识库](验收证据/新版_07_资源知识库-1440.png) |
| 状态与限制 | **已实现。** 资源只来自六个模拟案例，是“案例参考”，不是库存、货号或可采购物料。案例里没有出现的“非遗工艺”没有补编。留出评测用的案例五不进入推荐，也不在任何界面和导出中显示为来源。 |

### 2. 自然语言需求解构

> 将感性审美、穿搭场景、情绪偏好与使用人群需求拆解为风格调性、廓形要求、面料质感、工艺细节、色彩体系、场景适配度六大维度。
> 输出物：定制需求结构化参数清单、客户情绪审美标签报告

| 项 | 内容 |
| --- | --- |
| 衣诺怎么做 | 两层解构。① **逐句原话审计**：把客户的话拆成句子，每句对到方案的八个栏位（品类、版型结构、领型、面料、色彩、装饰纹样、长度比例、松弛余量），标出“已落实 / 间接满足 / 被改了 / 前后矛盾 / 没落实 / 交给设计师 / 客户已确认”，并区分“硬约束（必须满足）”和“软偏好（可以协商）”。② **六维报告**：按命题的六大维度归类，另补情绪审美、使用场景、使用人群，共九维；每一维只引用会话里真实存在的原话编号。 |
| 在原型哪里看 | ① 核对需求：左栏客户原话按状态着色，点一句看依据和落在哪个栏位；中栏列出“需要处理的句子”；展开「需求维度报告（风格、廓形、面料等九个维度）」看六维报告，可人工改分类并写说明。 |
| 证据 | [案例三完整台账](案例三_完整验收_20261119.json) 的“模型语义归类”；[案例二完整台账](案例二_完整验收_20261119.json)；截图 [核对需求](验收证据/新版_02_核对需求-1440.png)、[点选原话](验收证据/新版_03_点选原话-1440.png) |
| 状态与限制 | **已实现。** 拆句、映射和状态是 AI 的初步判断，界面默认标“待人工核对”。系统会自动校验“每句原话能在原文里原样找到”和“资源编号在库里”，不校验语义是否判断正确。九维报告只在两套案例上做过人工核对，没有大规模专家评估，不宣称准确率。 |

### 3. 资源匹配与方案初稿

> 匹配集团现有版型、面料、工艺，输出含风格定位、面料推荐、版型选择、工艺组合、适配场景与设计亮点的参考初稿；最终定稿、报价、商务洽谈及合同签订由业务人员完成。
> 输出物：海派定制整体方案初稿、资源匹配适配说明、方案可行性提示

| 项 | 内容 |
| --- | --- |
| 衣诺怎么做 | 先用硬约束排除不合适的资源，再按软偏好排序，从资源库里配出方案；每一栏都带资源编号和原话出处，资源库由两部分组成：上服 6 个案例拆出的做法（注明案例），和标“模拟库”的常见做法 + 模拟仓库（演示数据，可整份替换为上服真实数据）；面料一栏同时给出模拟仓库里对得上的货号和库存，交接单附领料建议。两部分都查不到的栏位明确标“库中暂无 · 待找样”，不硬凑。面料推荐按上服选面料的三条依据（风格适配、体感适配、体型适配）写理由，每条只引用客户原话和资源库记录的面料特点。第③步另有两个日常工具：「相似旧单」按客户原话找最像的旧单，用本单原话逐栏核对旧单做法，标出“可直接用 / 要按本单改 / 不能照搬”，能用的一键引用（升版、留痕，相关原话交设计师复核）；面料栏「换一块面料」并排给出候选料，各带三条依据和模拟库存。第②步「复述给客户听」把方案改写成客户听得懂的话（大模型只做改写，只复述方案已写内容），列出最可能听错的几处请客户逐条点“对 / 不对”，“不对”转给设计师并写进交接单。第④步可一键导出「项目交付包」：需求确认单、方案初稿、视觉需求包、交接单、修改记录五部分合成一个文件，目录写明每部分给谁用、对应命题哪条输出物。会改变方案的分歧（如“整体宽松”和“微微收腰”冲突、“梅花”被改成“植物暗花”）生成问题，业务员念给客户听、按客户回答点选，方案随之出新版本，已确认的栏位不被后续改动覆盖。多件套（如外套＋连衣裙）按单品分别匹配。 |
| 在原型哪里看 | ② 和客户确认：每题有选项、来源资源和“为什么要问”；右侧「方案速览」实时显示八栏当前值，刚改的栏标金色。③ 方案：「方案要点」逐栏显示值、资源编号和来源、生成后校验结果，可人工修改并写原因；「完整初稿」含风格定位、面料推荐、版型选择、工艺组合、适配场景与人群、设计亮点、资源适配说明和可行性待办，可下载 Markdown。 |
| 证据 | [案例二方案初稿](案例二_方案初稿_20261119.md)、[案例三方案初稿](案例三_方案初稿_20261119.md)；截图 [和客户确认](验收证据/新版_04_和客户确认-1440.png)、[方案](验收证据/新版_05_方案-1440.png) |
| 状态与限制 | **已实现。** 资源是案例参考，不代表可采购。系统不给具体尺寸、放量数值、报价，也不做制版；这些写成待办交给设计师和业务员。 |

### 4. 可视化 AI 绘图提示词

> 根据方案风格和参数生成适配主流 AI 设计工具的可复用提示词，支撑成衣、细节工艺与上身穿搭氛围图输出。
> 输出物：成套标准化 AI 视觉提示词、定制视觉效果需求包

| 项 | 内容 |
| --- | --- |
| 衣诺怎么做 | 按当前方案版本，用同一组锁定参数生成三类提示词：成衣挂拍、面料细节、上身效果；两件套要求所有单品同框。方案改了，提示词跟着当前版本重新生成，前后一致。客户带来的参考图可以上传：本机视觉模型看领型、门襟、纽扣、花纹四项，再和客户原话比对，找出“图和话对不上”的地方（例如参考图是立领，客户说“脖子比较短领子不能太高”）。配置生图接口后可**直接出图**：按当前方案一键出三张效果图，每张出完用本机视觉模型逐项核对领型、门襟、纽扣、纹样，对不上自动重画一次，结果写进台账；外部工具生成的效果图也可以传回来，按方案逐项核对。 |
| 在原型哪里看 | ③ 方案 →「效果图」：效果图画廊（一键出三张，每张带自动核对结果），提示词收在下方，可复制到外部工具。左栏「参考图」：拖入或选择图片，约十几秒到 1 分钟出结果，冲突卡片点一下就跳到对应原话。 |
| 证据 | 两套案例 JSON 里的“视觉需求包”；[新版界面验收](验收证据/新版界面验收.json) 的参考图记录 |
| 状态与限制 | **已实现（需配置付费生图接口）。** 演示环境接入 OpenAI 兼容生图接口，每张约 40 秒到 2 分钟；未配置时（`IMAGE_PROVIDER=none`）只输出提示词。效果图是沟通参考，不是成衣承诺。看图只采信四项，把握最高只算“疑似”；衣长、廓形、颜色交给人看。视觉模型有已知误识别：把案例六的交领识别成立领，所以看图结果必须人工复核。 |

### 5. 全流程业务台账

> 记录需求解构、资源匹配、方案生成与视觉辅助动作，归集项目信息、客户需求、方案成果与资源使用情况，支持导出归档。
> 输出物：可编辑、可上报的定制业务专题台账

| 项 | 内容 |
| --- | --- |
| 衣诺怎么做 | 每一步都留痕：导入、审计、客户确认（问了什么、客户选了什么、方案哪一栏从什么改成什么）、人工修改（必须写原因）、参考图解析、视觉提示词。每次改动生成新方案版本，旧版本保留。交接单汇总当前方案、客户确认结果、交给设计师判断的事项和打样核对项。 |
| 在原型哪里看 | ④ 交接：「交接单」可一键复制；「修改记录」按时间列出全部事件，可导出可编辑表格（CSV）和完整数据（JSON）。 |
| 证据 | [案例二 CSV](案例二_完整验收_20261119.csv)、[案例三 CSV](案例三_完整验收_20261119.csv)、两套完整 JSON；截图 [交接](验收证据/新版_06_交接-1440.png) |
| 状态与限制 | **已实现。** 台账导出包含客户原话，应按客户资料管理。没有对接集团的上报系统，“可上报”指导出的 CSV/JSON 可以直接交给业务系统或人工上报。 |

## 三、痛点场景对应

| 命题列出的痛点 | 衣诺的对应设计 |
| --- | --- |
| 感性、碎片化需求难以转化为面料、领型、廓形、工艺等专业参数，沟通链路长且依赖资深经验。 | 逐句原话审计把每句话落到具体栏位；只追问会改变方案的问题，题目和选项可以直接念给客户听，新人也能照着问。 |
| 海派版型、特色面料、经典工艺与历史案例未数字化结构化，难以快速检索匹配。 | 资源知识库 9 类 + 历史案例，带标签、使用规范和来源，可筛选、可导出；方案里的编号能反查。 |
| 缺少即时可视化效果参考，客户意向确认慢、签单周期长、试错成本高。 | 按当前方案版本生成三类提示词，可直接用于外部生图工具；客户的参考图能当场和原话比对，提前发现分歧。付费生图本轮未开启。 |
| 方案输出缺少统一标准，新人上手慢，难以沉淀海派定制风格体系。 | 统一的八栏方案结构和完整初稿模板；每栏写明来源，没有来源的明确标出；交接单格式固定。 |
| 洽谈、方案与资源匹配依赖手工台账，业务复盘与案例复用困难。 | 全流程自动留痕、版本化，CSV/JSON 导出可直接归档复盘。 |

## 七、没做到或有限制的地方

- 付费生图没有开启，原型只输出提示词。
- 看图只采信四项、最高“疑似”；案例六交领被误识别为立领，必须人工复核。
- 九维语义归类和逐句审计没有经过独立服装专家的大规模评估，不宣称准确率；留出案例五只运行过一次，不能据此证明泛化。
