## 一、已实现（功能都在本机可跑）

**听需求与审计**
- 六个示例案例都能一键建会话；案例五是留出测试案例，开发和演示都不使用。
- 把客户口述拆成逐句原话，对到八个设计字段，标出七种状态（有冲突、被改写、未落实、需设计师判断、间接体现、已落实、已与客户确认）。
- 程序规则兜底复核：宽松要求遇上收腰判冲突；客户明说的纹样或颜色没出现在方案里，判被改写或未落实；领宽这类交设计师判断。

**找资源**
- 资源知识库提供只读分类目录：当前共 43 项，其中 40 项有开发案例依据并可进入推荐；可按类型、风格和场景筛选，展示来源、适配规范与缺失元数据，并可导出 CSV。
- 每栏写明资源编号、名称、来源案例；资源只引用资源库（案例资源 + 模拟库）里真实存在的编号，对不上就标“库中暂无 · 待找样”，不编。
- 硬约束当过滤条件，软偏好只用来排序，两者分开处理。
- 命中身形规则（溜肩、小肚腩、手臂粗、内搭等）会把处理方式写进方案，溜肩这类交设计师判断。
- 未记录的库存、货号、价格、成分、克重、可采购性和人群信息保持空白，不用案例标签补齐。

**和客户改**
- 只生成"会改变方案"的客户问题，选项来自资源库，另有一个"坚持原话要求"选项；所有选项都改不动方案的问题直接丢弃。
- 客户每回答一次，方案升一个版本，相关原话改为"已与客户确认"，台账追加一条，只改相关栏位。
- 业务员可手动改一栏（必须填原因），同样升版记台账。同一问题重复选同一答案不会重复升版。

**交接与出图辅助**
- 交接单六部分：当前方案、和客户确认的结果、请设计师判断、待办、打样核对项、不由系统决定的事项。可一键复制，无 docx/pdf 导出。
- 生成三类效果图提示词（成衣挂拍、面料细节、上身效果），确定性输出、可复制。
- 上传参考图做解析并提示与口述的冲突；上传外部生成的图做逐项核对。
- 看图只采信领型、前襟闭合、纽扣、花纹四项，把握最高"疑似"；衣长、廓形、颜色不采用模型判断，界面显示"请人工确认"。

**从零生成方案**
- 只给口述（不给已有方案）时，用程序规则从资源库匹配出第 1 版方案，再对初稿做审计、生成问题。品类一栏取自客户口述（资源库没有独立品类项），找不到资源的栏标"无出处"。
- 多件套按单品分别匹配。外套的肩型、袖管和内搭放量不会自动复制到连衣裙；整体风格也不会被自动等同为具体植物暗花。

**需求报告、方案与台账**
- 真实模型把原话归入九个维度：官方六维、情绪与审美、使用场景、使用人群。每个引用都校验为会话内真实原话；结果先标“待人工核对”，业务人员可修正类别、保存说明并留下修订历史。
- 方案初稿覆盖风格定位、面料推荐、版型选择、工艺组合、适配场景与人群、色彩纹样松量、设计亮点、资源适配和可行性提示，可下载 Markdown。
- 台账格式为“衣诺业务专题台账 v2”，JSON 包含完整会话、需求报告、方案、资源适配、视觉需求包和人工说明；CSV 可按类别编辑。

**界面**
- 首页：标题“客户说了什么？”，一个输入框贴客户原话；可选“＋ 附上已有方案（可选）”展开八栏输入，附了方案就核对已有方案，没附就从零生成；下面一排预置示例案例按钮（不含案例五），右侧是“最近的洽谈”列表；按钮叫“开始分析”，等待时显示四步进度；右上角可进“资源知识库”。
- 工作台：顶部步骤条四步——①核对需求 ②和客户确认 ③方案 ④交接；完成的步骤打勾，“和客户确认”上显示还剩几个问题。左侧固定显示客户原话，点一句可看它对应方案哪一栏和判断理由，参考图上传也在左侧。
- ①核对需求：先给结论（几个问题要问客户、几件交给设计师、几句已落实或间接满足），然后列需要处理的句子；“已落实的句子”“不用问客户的项”“九维需求报告”默认收起。
- ②和客户确认：一次问一题，选项是卡片，答完显示“方案已更新到 vN”和哪一栏从什么改成什么，可“改选”。
- ③方案：三个视图“方案要点 / 完整初稿 / 效果图”；改过的栏显示第 1 版旧值（划线）；每栏可展开出处；没出处的栏标“无出处”；每栏可人工修改且必须填原因。
- ④交接：交接单为主，“修改记录（台账）”在旁边切换。
- 界面状态名改成大白话：有冲突→“前后矛盾”，被改写→“被改了”，未落实→“没落实”，需设计师判断→“交给设计师”，间接体现→“间接满足”，已与客户确认→“客户已确认”，已落实不变。讲技术或评测时仍保留原状态名。
- 七种状态一状态一色，无出处有醒目样式；窄屏可堆叠，支持键盘焦点和减少动效。
- 另有一套纯前端离线演示模式，不连后端、不调模型，用于断网或快速讲流程。
