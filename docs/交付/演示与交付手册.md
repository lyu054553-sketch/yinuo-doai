# 衣诺 · 演示与交付手册

给现场演示的人、和比赛对接的人看。看完应该能：在本机把后端和前端起起来，用案例二或案例三走完“听需求 → 找资源 → 客户确认/人工核对 → 方案与台账导出 → 交接”，并知道哪些话能说、哪些不能说。

演示采用本机环境（后端 8100、前端 5173、视觉服务 8001），不依赖外部测试链接。此前的临时外网入口已失效，不再作为交付入口。视觉服务已于 2026-11-24 恢复，参考图可以现场上传核对。

界面布局：左侧悬浮玻璃导航栏（新建洽谈、资源知识库、最近洽谈）；每场洽谈是三栏工作台——左栏客户原话和参考图，中栏当前步骤，右栏「方案速览」（核对需求、和客户确认两步显示，刚改的栏位标金色）。顶部是四步进度：核对需求 → 和客户确认 → 方案 → 交接。

---

## 一、本机启动（三个终端）

在项目根目录操作。后端、视觉服务和前端各占一个终端，顺序无所谓，但**演示前先确认都起来了**。

```sh
# 终端 1：后端（端口 8100，连真实模型）
python3 orchestration/start_backend.py
```

要现场直接出效果图，启动后端前先设生图接口（OpenAI 兼容 `/images/generations`，付费；Key 只放环境变量，不写进文件）：

```sh
export IMAGE_PROVIDER=openai_compatible
export IMAGE_BASE_URL=https://<生图服务地址>/v1
export IMAGE_MODEL=<生图模型名>
export IMAGE_API_KEY=<你的 Key>
python3 orchestration/start_backend.py
```

不设时 `IMAGE_PROVIDER=none`，效果图页只给提示词。

```sh
# 终端 3：视觉服务（端口 8001，本机推理，不调外部服务）
python3 orchestration/start_vision.py
```

视觉服务第一次使用前要建依赖环境，放在 iCloud 同步目录之外（项目在「文稿」里，macOS「优化存储」会把仓库内 `.venv` 的文件清成云端占位，推理会一直等到 300 秒超时）：

```sh
uv venv ~/.local/share/yinuo/venv-vision --python 3.12
uv pip install --python ~/.local/share/yinuo/venv-vision/bin/python -r vision/requirements.txt
```

视觉服务还需要本机 Ollama 已拉取 `qwen2.5vl:7b`、`qwen2.5vl:3b`。启动后 `curl http://127.0.0.1:8100/api/health` 应显示 `"vision_ok": true`；为 false 时界面会提示“看图服务本次未启用，文字核对不受影响”，不会让人传了再失败。

```sh
# 终端 2：前端（端口 5173，连上面的后端）
cd frontend
npm run dev -- --host 127.0.0.1
```

浏览器打开 `http://127.0.0.1:5173`。

补充说明：

- 后端接的是本机 Magpie 服务的 DeepSeek V4.1 Flash，密钥从环境变量 `MAGPIE_API_KEY` 读，**不要写进命令、文档或截图**。
- 第一次看图要加载模型，约 1 分钟；之后通常十几秒。录视频前先传一张图预热。
- 装环境用 `backend/requirements.txt`；前端先 `npm install` 一次。

## 二、8100 真实模型 vs 5174 离线模拟，别演混

现场有两种跑法，**结果和口径完全不同**：

| | 8100 + 5173（真实模式） | 5174（离线模拟） |
|---|---|---|
| 怎么启动 | 上面两条命令 | 只起前端，见下 |
| 谁在判断 | 真实模型拆句判断 + 程序规则 | 内置示例数据，不调任何模型 |
| 结果能不能当成绩说 | 可以作为本轮真实效果参考 | **不能**，只能证明界面流程跑得通 |
| 网络断了会怎样 | 创建会话会失败并给中文提示 | 照常演示 |

离线模拟的启动命令：

```sh
cd frontend
VITE_USE_MOCK=1 npm run dev -- --host 127.0.0.1 --port 5174
```

浏览器打开 `http://127.0.0.1:5174`。

离线模式的已知限制：**会话存在内存里，刷新页面后首页的洽谈记录就清空**；只有案例二有完整的三问流程，其他案例只展示审计结果、不生成追问。演示前请提前说明，避免现场被当成"丢了数据"。

**一句话原则：讲界面流程用 5174 最稳；讲"模型真的能判出来"必须用 5173＋8100，并且说明这是开发自检、不是正式评测成绩。**

## 三、三分钟主线演示：案例二 + 参考图

录视频前：三个服务都起来；先用任意一张图预热一次看图；准备好一张**自己生成的立领外套图**做参考图（不要用上服的真实照片，真实照片只用于测试）。视频要上传成**公开可访问的直链**，这是赛道的提交要求。

**0:00–0:20｜首页。** 左侧是工作台导航和吉祥物“衣诺”。选“案例二”，客户原话和已有方案自动带入，点“开始分析”。真实模式要等模型返回，视频里剪掉等待，但不要把预置结果说成实时输出。

**0:20–0:55｜核对需求。** 左栏客户原话按状态着色。点“最好是梅花”（被改了）、“整体宽松舒展一点”（前后矛盾），说明每句都对到方案的栏位，并标出硬约束还是软偏好。指一下右栏「方案速览」顶部的校验：原话可溯源、资源编号在库。强调颜色是 AI 初判，业务员要复核。

**0:55–1:35｜和客户确认。** 依次回答梅花暗纹、腰身、内搭三题。每答一题，中栏提示“方案已更新到 vN”，右栏对应栏位变成金色。领宽这类专业问题交给设计师，不问客户。

**1:35–2:00｜参考图。** 左侧“最近洽谈”切到案例一，把立领外套图拖进“参考图”。等待时有吉祥物和计时。结果出来：领型“立领 · 疑似”，并提示“参考图为立领，客户说‘脖子比较短领子不能太高’”。点冲突卡片，对应原话和右侧领型栏高亮。说明看图只采信四项，最高只算“疑似”，衣长、廓形、颜色交给人看。

**2:00–2:30｜方案。** 切回案例二。「方案要点」每栏有资源编号和来源（案例或“模拟库”），面料一栏下方有模拟仓库的现货货号和库存。进「效果图」，展示三类提示词，说明付费生图没开，提示词复制到外部工具使用。

**2:30–2:52｜交付。** 点「导出项目交付包」：一个文件包含需求确认单、方案初稿（面料三条依据）、视觉需求包、交接单（含打样核对、领料建议）、修改记录，目录写明每部分给谁用。收尾一句：“客户说过的每句话都能追到方案、确认和修改记录。”

**2:52–3:00｜收口。** 衣诺帮业务员核对和交接，不替客户、设计师、量体师或供应链做决定。

**可选加演（不占三分钟主线）：手改一栏到 v5。** 在方案里手动改“色彩”，必须填写修改原因，确认后升到 v5，台账再记一条。

## 四、提示词、外部图核对、交接单，分别在哪里

| 要演示的东西 | 界面位置 | 接口（给技术对接人） |
|---|---|---|
| 三条效果图提示词 | 工作台"方案 → 效果图"，三种类型：成衣挂拍、面料细节、上身效果，每条可复制 | `GET /api/sessions/{id}/prompts` |
| 上传参考图、看疑似冲突 | 左侧"客户原话"区域的参考图上传 | `POST /api/sessions/{id}/reference` |
| 上传外部生成的图做核对 | "方案 → 效果图"里的外部图片上传 | `POST /api/sessions/{id}/images`（上传文件 + 类型） |
| 交接单 | "交接"步骤，Markdown 文本 | `GET /api/sessions/{id}/handoff` |

参考图上传支持拖放；看图服务没开时入口会直接说明，不会让人传了再失败。上传新图用参考图标题旁的“换一张”。

关键口径：

- **默认不出图。** 只生成提示词；效果图要人拿提示词去外部工具生成，再传回来核对。系统没有调用付费生图。
- **交接单六部分：** 当前方案、和客户确认的结果、请设计师判断、待办、打样核对项、不由系统决定的事项。
- **交接单可一键复制文本，但没有 docx/pdf 导出按钮。** 不要说"可以导出 Word"。
- **核对时衣长、廓形、颜色一律显示"请人工确认"**，不采用模型判断；领型、闭合、纽扣、花纹最高只显示"疑似"。

## 五、参考图冲突演示：用 c1 成衣图 + 低领口述

2026-11-24 在本机重新跑通（记录见 [新版界面验收](验收证据/新版界面验收.json)）：

1. 在案例一会话（客户说“脖子比较短领子不能太高”）上传一张立领外套图。测试时用的是案例一成衣图 `data/images/c1_garment.jpeg`；**录视频和对外演示请换成自己生成的图**，上服真实照片只用于测试。
2. 首次约 63 秒（加载模型），预热后约 7 秒返回。
3. 结果：领型“立领 · 疑似”、前襟“外露扣 · 疑似”，并提示**参考图为立领，客户说“脖子比较短领子不能太高”，请确认领高是否在可接受范围**。
4. 案例二的说法是“领子不要太高”，不在冲突规则的关键词里，所以参考图这段用案例一演示。
4. 讲解点：图只作参考，客户的话优先；冲突交给客户来定。

这条要如实说"疑似"，不要升级成"确定"。

## 六、看图模块的已知误差：不要剪掉，要主动说明

冻结的视觉模型把**案例六那件交领外套**的成衣图识别成了**立领**，于是拿它对照案例六方案时，"领型"会被判"不符合"。这是真实误差，**演示时不要跳过、不要剪掉、不要说成"正例全部通过"**。

如果现场展示这一项，请当场说明：

> "这是模型看错，衣服是交领，它看成立领了。所以我们对看图结果统一标'疑似'，由人来复核——这也是为什么衣长、廓形、颜色我们干脆不采用模型判断。"

这样讲反而更有说服力：系统知道自己会错，并且把纠错权留给人。

演示前也可运行 `python3 backend/app/media/demo_evidence.py`，检查两组图片与原始证据是否齐全，并生成逐项人工复核摘要。脚本不调模型或生图服务，也不判定视觉通过。

## 七、从零生成方案（可选加演）

只输入客户口述、不给已有方案，系统用程序规则从资源库里挑资源，生成第 1 版方案，再对这份初稿做审计。

- 演示用开发集里的口述（例如"面料想用醋酸""版型要不压肩""领子不要太高"这类），能看到资源被正确选中。
- 客户要的东西案例资源和模拟库里都没有（例如"一定要条纹"）时，会明确标“库中暂无 · 待找样”并生成待办，**不会编资源编号**。这是讲"不编造"的好素材。模拟库和模拟仓库要说清楚是演示数据。
- 耗时比案例二长（一次真实从零生成约 30 秒），演示时提前打好预防针，或者先把结果生成好再切过来看。

## 七之二、团体职业服案例（第二套完整案例）

工作台可直接打开“案例三：团体职业服模拟验收（最终修复版）”。当前为真实模型生成的 v4 方案，演示重点：

- 20 位门店品牌顾问、品牌发布会和日常客户接待场景已进入九维需求报告；
- 外套与连衣裙分别匹配，外套肩型和袖管放量没有复制给连衣裙；
- “简洁大气”没有被误套成具体植物暗花；
- “蓝色或灰色”两个待确认选项被完整保留，没有只截取一个；
- 10 份业务说明、九维人工核对、内搭确认和人工纹样澄清共形成 17 条台账；
- 三类提示词要求成套服装所有件同框，可导出 Markdown、CSV 和 JSON。

完整文件见 [案例三完整验收](案例三_完整验收_20261119.json)。

## 八、现场常见问题，照着答

| 现场会问 | 怎么答 |
|---|---|
| "这些面料你们有货吗？" | 是上服案例里出现过的参考，不是库存；有没有货要问供应链。 |
| "准确率多少？" | 本轮正式评测：注入问题集检出 32/54，同一模型通用问法对照 33/54，**没有优势**；开发集 18/18 但开发时反复看过，不能外推。数字和局限见《开发状态》。 |
| "留出集怎么样？" | 冻结后只跑过一次 Case 5：拆句召回 8/8、字段召回 7/8、状态完全一致 5/8。这个案例没有标准问题句，问题检出 0/0，不能据此说未见案例的问题检出已经验证。 |
| "会不会瞎编？" | 原话和资源编号做了自动校验，本轮 75 次输出零违规；但解释性文字要人看，我们不称"零幻觉"。 |
| "能直接出效果图吗？" | 现在出的是提示词，图由外部工具或人来生成，再传回来核对；付费生图未启用。 |
| "尺寸、报价能出吗？" | 不出。量体、尺寸、报价、制版、采购、下单都由人决定。 |
| "上线了吗？" | 此前的临时外网测试入口已失效，当前演示使用本机环境（后端 8100、前端 5173），不依赖外部链接；不是正式生产上线，也没有多用户账号隔离或高可用承诺。 |
| "案例五呢？" | 冻结后只运行一次并保存在一次性目录中；不用于开发、调参和演示。 |
