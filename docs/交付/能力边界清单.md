# 衣诺 · 能力边界清单

**一句话：** 衣诺能帮业务专员把客户口述逐句对到八个设计字段、标出问题和出处的缺口，并陪着客户改版到能交接；它不判断材料有没有货、不替代设计师和量体师，也不做报价、制版、采购和下单。

本文给业务对接人和比赛对接人看。每条边界都写明限制、原因和对外说法。

---

## 1. 资源是案例参考，不是库存

- **边界：** 系统里能引用的版型、面料、工艺、纹样，全部来自上服已有案例中出现过的东西，每条都带案例出处（案例一……案例六）。它说的是"这个案例用过这类东西"，**不是"仓库里有这个、现在能下单"**。
- **为什么：** 系统只读案例整理数据，没有接入物料库存、供应商或价格系统。
- **怎么说：** "这一栏的出处是案例几，属于案例参考；能不能做、有没有料，要另外问供应链。"

## 2. AI 拆句、映射和状态判断必须人工复核

系统使用通用对话模型完成拆句和语义判断，再由程序规则补充核对，没有针对服装业务训练自研大模型。它可能漏判、多判、状态标偏，同一段口述重复运行时也可能出现不同结果。界面保留原话、字段、状态和理由，是为了让业务员快速复核，不是给出终审结论。客户回答和方案字段的人工修改可以保存并留痕；但不能据此理解为所有 AI 分类和状态都能直接在界面上纠正。

## 3. 硬性要求优先排除，个人偏好用于排序

在规则能够识别且资源信息足够的范围内，“一定、不能、不要”等要求优先用于排除不符合的候选；“最好、偏向”等偏好用于候选排序。识别不清、资源信息缺失或没有合适候选时，系统保留客户要求，并生成确认问题或人工待办，不声称所有硬性要求都已被自动、完整执行。

## 4. 自动校验只覆盖原话和资源编号

程序会校验引用的文字是否能在本次客户原话中定位，以及资源编号是否存在于当前资源库。本轮 D2 的 75 次成功输出中，这两类指定检查未发现违规；该结果只适用于本次评测和检查范围，不等于“零幻觉”。材料特性、工艺可行性、库存、价格和解释性文字仍需人工核查。

## 4b. 相似旧单、面料备选、复述确认只辅助，不拍板

- **边界：** 相似旧单和面料备选全部是程序规则：用本单客户原话核对旧单做法和候选面料，只标“能不能用”，引用或换料后相关原话交给设计师复核，不记成客户已确认。复述确认里，大模型只负责把方案改写成口语、把可能听错的点问成是非题，不新增内容、不承诺价格工期；客户说“不对”的地方转给设计师。
- **怎么说：** “衣诺帮业务员少走弯路，但哪块料、哪种做法，最后还是设计师和客户定。”

## 5. 库中暂无的栏位必须人工找样

- **边界：** 资源库 = 上服案例拆出的做法 + 标“模拟库”的常见做法与模拟仓库（演示数据，不是上服真实库存，落地时整份替换）。客户要的东西两部分都没有（例如“一定要条纹”），该栏会明确标成“库中暂无 · 待找样”，并留一条待办“寻找对应面料/纹样”。系统**不会**编一个资源编号来填空。
- **为什么：** 宁可空着让人去找，也不能给一个假出处让设计师照着做。
- **怎么说：** "标了‘库中暂无’的栏，就是需要人去市场上找样；找到之前这一栏不算落实。模拟库和模拟仓库是演示数据，接上服真实数据后替换。"

## 6. 看图只采信四项，且把握最高只到"疑似"

- **边界：** 参考图和效果图核对时，只采信**领型、前襟闭合方式、纽扣是否可见、花纹**四项，且把握程度最高显示"疑似"，要人确认。**衣长、廓形、颜色三项不采用模型判断**，界面直接显示"请人工确认"。
- **为什么：** 本地视觉模型在这三项上不可靠，采用它反而会误导。
- **怎么说：** "看图能提示'这像立领''这像有外露扣子'，但要人点头；衣长、廓形、颜色一律由人看。"

## 7. 视觉模型有已知误识别，案例六正例核对未通过

- **边界：** 冻结的视觉模型把案例六那件**交领**外套的成衣图识别成了**立领**，导致对照案例六方案时"领型"一项被判"不符合"。这是真实存在的误差，**不能算作视觉正例全部通过**，也不能在演示里剪掉或掩盖。展示这一项时，必须现场说明"这是模型看错，需人工复核"。
- **为什么：** 视觉模型已冻结、不做训练；标准答案和数据也未改动，以保留真实误差。
- **怎么说：** "我们的看图模块有明确的已知误差，案例六这件交领被看成立领；所以我们把它的把握标成'疑似'，由人来定。"

## 8. 付费生图未启用

- **边界：** 生图默认关闭（只生成提示词、不真正出图）。效果图核对功能可用，但用的是**人工在外部工具生成的图，或手头现成的图**，上传进来做核对。系统没有调用任何付费生图服务。
- **为什么：** 付费调用需要项目负责人另行授权；当前演示不需要真出图也能讲清楚流程。
- **怎么说：** "系统出的是给生图工具用的提示词；图由人或外部工具生成后再传回来核对。我们不宣称已生成付费效果图。"

## 9. 最终量体、尺寸、报价、制版、采购、下单由人决定

- **边界：** 系统不给出具体尺寸数值（如胸围放几厘米），不做量体，不出报价，不做制版，不采购，不下单。涉及尺寸的地方一律写"量体后确认""打样试穿核对"。
- **为什么：** 这些是设计师、量体师和供应链的专业判断与合同行为，超出本系统范围。
- **怎么说：** "衣诺负责把需求理清、把该问的问出来、把该交接的写清楚；定尺寸、定价、定版、下单由人来做。"

## 另外几条容易被误会的边界

| 容易误会 | 实际情况 |
|---|---|
| "系统里有六个案例，就是六套成品可选" | 案例是审计和匹配的参考样本，不是可选商品目录。 |
| "案例五也能演示" | 案例五只在冻结后完成唯一一次留出评测，不用于开发、调参或演示；一次性锁和原始结果均已保留。 |
| "留出集说明问题检出已验证" | Case 5 没有标准问题句，问题检出是 0/0；不能据此宣称未见案例的问题检出泛化。 |
| "检出率比通用问法高" | 本轮正式评测里衣诺 32/54、通用问法对照 33/54，**没有检出优势**；数字和局限见《开发状态》。 |
| "已经生产上线" | 当前是依赖本机环境（后端 8100、前端 5173）的演示原型；此前的临时外网入口已失效，没有固定域名、多用户隔离、高可用或生产安全审计。 |
| "交接单能导出 Word/PDF" | 交接单是页面上的 Markdown 文本，可一键复制；没有 docx/pdf 导出按钮。 |
| "从零生成方案每一栏都有出处" | 从零生成会尽量给资源出处（含模拟库），找不到的栏标“库中暂无 · 待找样”；品类一栏直接取自客户原话。 |
| "多件套都能分别匹配" | 目前只覆盖"外套＋连衣裙"这一种多件套形态；客户说大衣、风衣等资源库外的衣种时，宁可不选也不硬凑。 |
| "离线演示和真实后端结果一样" | 离线模式用内置示例数据跑界面流程，不调模型；真实后端的数字才算数。 |
