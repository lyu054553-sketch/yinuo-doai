# 衣诺 · 开发总体说明与接口约定

所有开发 AI 开工前都必须先读完本文件。**本文件是各 AI 之间唯一的约定。** 任何人都不能自行修改；需要改动时，写进 `docs/开发/接口变更请求.md`，由项目负责人决定后统一更新。

## 1. 产品是什么

上服集团 FDE 赛题「海派定制服饰 AI 需求解构与可视化 Agent」的参赛作品，名叫“衣诺”，**11 月 25 日截止提交**。使用者是定制业务专员，用在和客户的首次洽谈中：

1. **听需求**：输入客户口述，可附参考图。系统把口述逐句拆开，对应到上服的八个设计字段，标出每句话的状态（已落实、被改写、有冲突等）。
2. **找资源**：从上服案例里出现过的版型、面料、工艺、纹样中，挑出合适的组合。每一项都注明出处，没有出处的项不能标为可用。
3. **和客户一起改**：只问会改变方案的问题。客户每回答一次，方案升一个版本，并记一笔台账。
4. **交接**：生成效果图提示词和效果图，出图后自动核对；最后输出设计师拿到就能接手的交接单。

系统有两种模式：

- **审计已有方案**：输入客户口述和一份已有的设计方案（例如上服案例里原有的转化结果），逐句检查方案有没有落实客户的话。这是演示主线，用案例二。
- **从零生成方案**：只输入客户口述，由系统匹配资源生成初稿，再做审计。

相关资料（只读）：

- `DOAI参赛产品选题调研.md`：产品方案，开发者必读“首版演示和赛题对齐”和“3 分钟 Demo 的编排”两节。
- `data/README.md`、`data/cases.json`、`data/resources.json`、`data/images.json`、`data/workflow.json`：已整理好的案例数据。
- `prototype/case2.html`：**早期界面草图，只用来参考交互，不作为代码基础。**
- `vision/`：视觉模型的评测结论和本地推理服务，结论见第 7 节。

## 2. 技术选型

| 部分 | 选型 | 端口 |
|---|---|---|
| 后端 | Python 3.11+，FastAPI，Pydantic v2，uvicorn | 8100 |
| 前端 | Vite + React + TypeScript，不引入大型 UI 库 | 5173；开发时用 Vite 代理把 `/api` 转到 8100 |
| 对话大模型 | 统一走 OpenAI 兼容接口，默认连本机 Ollama（`http://127.0.0.1:11434/v1`） | — |
| 生图模型 | 适配器模式；默认 `none`，只生成提示词，不出图 | — |
| 视觉服务 | 复用现有 `vision/server_local.py`，启动时用 `--port 8001` | 8001 |
| 数据存储 | 本地 JSON 文件（`backend/storage/`），不需要数据库 | — |

配置一律从环境变量读取。`backend/.env.example` 列出所有变量，真实的 `.env` 不提交：

```
MOCK_MODE=1                  # 1 = 不调大模型，直接用 data/cases.json 的标注结果
LLM_BASE_URL=http://127.0.0.1:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=qwen2.5vl:7b       # 可换成任何 OpenAI 兼容的模型
IMAGE_PROVIDER=none          # none | openai_compatible
IMAGE_BASE_URL=
IMAGE_API_KEY=
IMAGE_MODEL=
VISION_URL=http://127.0.0.1:8001
```

## 3. 目录归属（谁能改哪里）

| 目录 | 负责的 AI | 说明 |
|---|---|---|
| `backend/`（不含下面两项） | 后端核心 | 包括 `main.py`、`schemas.py`、存储、需求解构、匹配、审计、追问、改版、交接单 |
| `backend/app/media/`、`backend/app/routers/media.py` | 出图与视觉 | 效果图提示词、生图适配器、参考图解析、效果图核对 |
| `frontend/` | 前端 | 全部界面 |
| `eval/` | 评测 | 评测脚本和报告 |
| `data/`、`vision/`、`prototype/` | 无人负责 | **只读，任何 AI 都不能修改** |
| `docs/开发/` | 项目负责人 | AI 只能往 `接口变更请求.md` 里追加内容 |

规则：

- 只改自己负责的目录。要读别人的代码可以，要改就写变更请求。
- 不运行任何 git 命令（不提交、不切分支、不还原）。版本由项目负责人统一提交。
- 每个 AI 在自己的目录下维护一份 `WORKLOG.md`：做了什么、怎么运行、已知问题。

## 4. 固定词表

**八个设计字段**（顺序固定，作为 JSON 值时直接用中文）：
`品类`、`版型结构`、`领型`、`面料`、`色彩`、`装饰纹样`、`长度比例`、`松弛余量`

**原话状态**（严重程度从高到低）：
`有冲突`、`被改写`、`未落实`、`需设计师判断`、`间接体现`、`已落实`、`已与客户确认`

定义见 `data/cases.json` 的 `status_definitions`。其中 `已与客户确认` 是系统追加的状态：客户回答了相关问题之后，原话变为这个状态。

**原话强度**：`硬约束`、`软偏好`、`目标`、`描述`

**看图把握程度**：`确定`、`疑似`、`看不出`

## 5. 数据结构

JSON 的键用英文，值里的字段名和状态用中文词表。时间统一用 ISO 8601 字符串。

```ts
type Field = "品类"|"版型结构"|"领型"|"面料"|"色彩"|"装饰纹样"|"长度比例"|"松弛余量";
type Status = "有冲突"|"被改写"|"未落实"|"需设计师判断"|"间接体现"|"已落实"|"已与客户确认";
type Strength = "硬约束"|"软偏好"|"目标"|"描述";

interface Session {
  id: string;
  title: string;
  mode: "审计已有方案" | "从零生成方案";
  source: "mock" | "llm";          // 本次解构来自标注数据还是大模型
  created_at: string;
  input: { text: string; existing_spec: Record<Field, string> | null; sample_id: string | null };
  utterances: Utterance[];
  spec_versions: SpecVersion[];    // 最后一个是当前版本；version 从 1 开始
  questions: Question[];           // 问客户的问题
  designer_items: DesignerItem[];  // 交给设计师判断的事项
  skipped: SkipItem[];             // 决定不问的字段及原因
  ledger: LedgerEntry[];           // 按时间顺序追加，不删除
  reference: ReferenceAnalysis | null;   // 出图与视觉负责
  images: GeneratedImage[];              // 出图与视觉负责
}

interface Utterance {
  id: string;                      // "u1"、"u2"……
  text: string;                    // 必须是 input.text 的原文子串
  start: number; end: number;      // 在 input.text 中的字符位置，end 不含
  type: string;                    // 如 风格、身形、领型、松量、纹样、场景
  strength: Strength;
  status: Status;                  // 由 mappings 中最严重的状态得出
  mappings: Mapping[];
  resolved_by: string | null;      // 解决它的 question id
}

interface Mapping {
  field: Field;
  garment: string | null;          // 多件套时注明单品，如 "外套"
  status: Status;
  note: string;                    // 给人看的一句理由
  rule_id: string | null;          // 用到的身形规则，如 "R2"
}

interface SpecVersion {
  version: number;
  created_at: string;
  reason: string;
  fields: Record<Field, SpecField>;
}

interface SpecField {
  value: string;                   // 多件套写成 "外套：……；连衣裙：……"
  resource_ids: string[];          // 引用 data/resources.json 的 id，如 ["S1","SH1"]
  utterance_ids: string[];         // 这一栏落实了哪些原话
  origin: "资源库" | "已有方案" | "客户确认" | "人工修改" | "无出处";
  confirmed: boolean;              // 客户已确认
}

interface Question {
  id: string;                      // "q1"……
  utterance_ids: string[];
  field: Field;
  title: string;                   // 如 "暗纹选哪一种？"
  context: string;                 // 客户原话和方案的出入
  why: string;                     // 为什么问：答案会改变哪一栏
  options: Option[];
  answer: string | null;           // 选中的 option id
}

interface Option {
  id: string;
  label: string;
  detail: string;                  // 如 "P3 · 来源案例六"
  resource_ids: string[];
  patch: Partial<Record<Field, string>>;   // 选中后方案要改成什么
  note: string;                    // 写进台账的原因
  todo: string | null;             // 选中后产生的待办，如 "寻找梅花暗纹面料"
}

interface DesignerItem { id: string; utterance_ids: string[]; field: Field; text: string; }
interface SkipItem { field: Field | "领宽" | string; reason: string; }

interface LedgerEntry {
  version: number;
  at: string;
  action: "导入" | "审计" | "客户确认" | "人工修改" | "参考图解析" | "出图" | "核对";
  summary: string;                 // 一行，如 "【装饰纹样】植物暗花 → 四瓣花散点"
  detail: string;                  // 原因和原话
  utterance_ids: string[];
  changed_fields: Field[];
}

interface ReferenceAnalysis {
  image_url: string;
  fields: Record<string, { value: string | boolean; confidence: "确定"|"疑似"|"看不出"; used: boolean }>;
  conflicts: { field: Field; message: string; utterance_ids: string[] }[];
  model: string;
}

interface GeneratedImage {
  id: string;
  version: number;                 // 依据的方案版本
  kind: "成衣挂拍" | "面料细节" | "上身效果";
  prompt: string;
  url: string | null;              // provider 为 none 时为 null
  provider: string;
  check: CheckResult | null;
}

interface CheckResult {
  items: { field: Field; expect: string; observed: string; verdict: "符合"|"不符合"|"看不出"; confidence: "确定"|"疑似"|"看不出" }[];
  model: string;
}
```

## 6. 接口

所有接口都以 `/api` 开头，返回 JSON；出错时返回 `{"error": "给人看的中文说明"}` 和对应的 HTTP 状态码。

| 方法与路径 | 负责 | 说明 |
|---|---|---|
| `GET /api/health` | 后端核心 | 返回 `{ok, mock_mode, llm_model, image_provider, vision_ok}` |
| `GET /api/samples` | 后端核心 | 6 个示例案例：`[{id, title, text, existing_spec, holdout}]`；案例五 `holdout: true` |
| `GET /api/resources` | 后端核心 | 原样返回 `data/resources.json` |
| `POST /api/sessions` | 后端核心 | 请求 `{text, existing_spec?, sample_id?, title?}`，完成解构、匹配（从零模式）、审计、生成问题，返回 `Session` |
| `GET /api/sessions` | 后端核心 | 列表 `[{id, title, created_at, version}]` |
| `GET /api/sessions/{id}` | 后端核心 | 返回 `Session` |
| `POST /api/sessions/{id}/answers` | 后端核心 | 请求 `{question_id, option_id}`，返回更新后的 `Session` |
| `PATCH /api/sessions/{id}/spec` | 后端核心 | 业务员手动改一栏：`{field, value, reason}`，返回 `Session` |
| `GET /api/sessions/{id}/handoff` | 后端核心 | 交接单：`{markdown}` |
| `GET /api/sessions/{id}/prompts` | 出图与视觉 | `{version, items: [{kind, text}], checks: [{field, expect}]}` |
| `POST /api/sessions/{id}/reference` | 出图与视觉 | 上传参考图（multipart，字段名 `file`），返回 `Session`（含 `reference`） |
| `POST /api/sessions/{id}/images` | 出图与视觉 | `{kind}` 按当前方案生成；或 multipart 上传一张外部生成的图（字段名 `file`，另带 `kind`）只做核对。返回 `Session` |
| `GET /files/...` | 后端核心 | 静态文件：上传和生成的图片、`data/images/` |

**示例模式（`MOCK_MODE=1`）**：`POST /api/sessions` 带 `sample_id` 时，不调大模型，直接用 `data/cases.json` 的标注生成 `Session`：原话用标注的拆句，位置由程序在原文中查找；方案用案例原有的 spec。匹配、追问、改版、台账、交接单都是程序逻辑，示例模式下照常运行。不带 `sample_id` 时返回 400，提示“示例模式只支持示例案例”。

## 7. 视觉模块（已冻结）

依据 `vision/results/benchmark_v2_report.md`，**不做任何训练**，只用现有的本地推理服务：

| 字段 | 处理方式 |
|---|---|
| 领型、闭合方式、纽扣是否可见、花纹 | 采用模型结果，把握程度最高只显示“疑似”，界面提示由人确认 |
| 衣长、廓形、颜色 | 不采用模型结果（`used: false`），界面显示“请人工确认” |

视觉服务没启动时，相关接口返回 503 和“视觉服务未启动”，其他功能不受影响。

## 8. 通用要求

- **不编造。** 资源只能引用 `data/resources.json` 里存在的 id；方案中没有出处的内容，`origin` 标为 `无出处`，界面要能看出来。
- **案例五是留出测试案例**，不能写进任何提示词示例、少样本示例或规则。
- **大模型输出一律做 JSON 校验。** 不合格就重试一次；还不合格，就返回明确的错误，不能硬凑结果。原话 `text` 必须能在原文中找到。
- **API Key 只从环境变量读取**，不写进代码、日志和前端。
- **界面文字和报错一律中文**，用业务员听得懂的话。
- **涉及付费的调用**（云端大模型、生图）在调用前先问项目负责人。
