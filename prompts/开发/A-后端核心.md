# 任务 A：衣诺后端核心

你负责“衣诺”的后端核心。先完整读完 `docs/开发/00-总体说明与接口约定.md`。这份约定是你和另外三个 AI（前端、出图与视觉、评测）之间唯一的对接依据，必须严格遵守。

## 你的范围

- **可以改：** `backend/` 下的所有文件，但不包括 `backend/app/media/` 和 `backend/app/routers/media.py`。这两处属于“出图与视觉”。
- **只读：** `data/`、`vision/`、`prototype/`、`docs/`。
- **不运行 git 命令。**
- 接口约定需要改动时，写进 `docs/开发/接口变更请求.md`，然后停下来问项目负责人。

## 建议结构

```
backend/
  app/
    main.py            # FastAPI 入口，挂载各路由和 /files 静态目录
    config.py          # 读环境变量
    schemas.py         # 约定第 5 节的全部数据结构（Pydantic）
    store.py           # Session 读写 backend/storage/sessions/*.json
    knowledge.py       # 读取 data/resources.json、data/cases.json；资源属性索引
    llm.py             # OpenAI 兼容客户端：JSON 输出、校验、重试一次、超时
    pipeline/
      extract.py       # 拆句和抽取约束（大模型）
      mock.py          # 示例模式：用 cases.json 的标注构造 Session
      match.py         # 资源匹配和身形规则（程序规则）
      audit.py         # 逐句判断状态（大模型判断，加程序规则复核）
      questions.py     # 生成客户问题、设计师事项、不问清单（程序规则）
      revise.py        # 回答问题或手动修改 → 方案升版本，记台账
      handoff.py       # 交接单 Markdown
    routers/
      sessions.py  samples.py  resources.py
      media.py           # 只写占位：注册约定里的三个接口，统一返回 501“出图与视觉模块开发中”，之后由“出图与视觉”替换
  storage/  tests/  .env.example  requirements.txt  WORKLOG.md
```

## 处理流程

**1. 拆句与抽取（大模型）**
- 把客户口述拆成原话，每句给出 `type`、`strength`，以及它对哪些字段提出了什么要求，例如：
  `{"field": "领型", "want": "领子低", "polarity": "要"}`
- 拆出的原话必须是原文子串，用程序计算 `start` 和 `end`。
- 少样本示例只能用案例一、二、三、四、六，**绝不能用案例五**。

**2. 得到方案第 1 版**
- 审计模式：用 `existing_spec`，各栏 `origin` 标为“已有方案”。尽量把每一栏的文字对应到资源 id；对应不上就留空，不要硬凑。
- 从零模式：由 `match.py` 为每一栏挑选资源。

**3. 资源匹配（程序规则，不调大模型）**
- 在 `backend/app/knowledge_attrs.json` 里给资源补充结构化属性，例如 `CL1: {"领高":"低","风格":"中式"}`、`S2: {"收腰":"微收"}`。
- 硬约束是过滤条件，违反就排除；软偏好只用来加分排序。
- 命中身形规则 R1–R8 的，把处理方式写进对应字段，并在映射里记下 `rule_id`。
- 没有任何原话涉及的字段，用资源库里最常见的取值，并写进 `skipped`。例如衣长：6 个案例全是“臀中”。
- 资源库里找不到的内容，`origin` 标为“无出处”。

**4. 审计（大模型判断加程序规则复核）**
- 逐句、逐个映射判断状态，状态只能从词表里选，`note` 要写一句人能看懂的理由。
- 程序规则至少覆盖：“宽松”类要求遇上“收腰”判为有冲突；客户明说的具体纹样或颜色没有出现在方案里，判为被改写或未落实。

**5. 生成问题（程序规则）**
- 有冲突、被改写、未落实，且属于客户能决定的事（纹样、色彩、版型、松量、面料）→ 生成客户问题。
  - 选项来自资源库，另加一个“坚持原话要求”选项。这个选项没有资源出处，选中后产生待办。
  - 内搭这类不对应资源的问题，用规则模板生成选项。
- 需设计师判断的 → 生成设计师事项，不问客户。
- **只问会改变方案的问题**：所有选项都改不动当前方案的问题，直接丢弃。

**6. 改版与台账**
- 回答问题或手动修改，方案都升一个版本，相关原话改为“已与客户确认”，并追加一条台账，写明改了哪一栏、因为哪句原话、其余几栏没动。
- 同一问题重复选同一个选项，不升版本。

**7. 交接单**
包括六部分：当前方案、和客户确认的结果、请设计师判断、待办、打样核对项（参考 `data/workflow.json` 第 5 步）、不由系统决定的事项。

## 里程碑（每个做完都停下来，向项目负责人汇报）

**M0 骨架与示例模式（最优先，目标 2–3 小时）**
- 完成约定第 6 节里属于你的全部接口；示例模式可以跑通 6 个案例；`media.py` 写好占位。
- 汇报：启动命令，以及用 curl 创建案例二会话、回答一个问题的示例。**前端会立刻改为调用你的接口**，所以这一步要快、要稳。

**M1 大模型解构与审计（审计模式）**
- `MOCK_MODE=0` 时，输入案例二的口述和原方案，结果应能标出“最好是梅花”被改写、“整体宽松”与“微微收腰”有冲突。
- 照实汇报案例一、二、三、四、六各自的结果和耗时，没做到的项要写明。正式评测由“评测”负责，你只做自检。

**M2 从零生成方案**
- 只输入口述就能生成第 1 版方案，每一栏都有出处，或者明确标为“无出处”。

**M3 稳健性**
- 大模型超时或输出不合格时，接口返回清楚的中文错误。
- `pytest` 覆盖：示例模式、改版、台账、交接单、JSON 校验失败的处理。

## 验收标准

- `uvicorn app.main:app --port 8100` 能启动；`GET /api/health` 正常返回。
- 示例模式下，案例二生成的会话包含以下内容：
  - 客户问题：纹样（梅花）、腰身（收腰）、内搭三个问题。
  - 设计师事项：领宽。
  - 不问清单：至少有色彩和衣长。
- 依次回答这三个问题后，方案到 v4，台账多出三条，交接单里能看到三个回答。
- 所有接口的返回都符合约定第 5 节的结构，字段名不多也不少。
- 原话和资源都不编造；案例五不出现在任何提示词示例里。

## 汇报方式

用中文写，尽量少用术语，开头一句话说结论，例如“M0 完成，前端可以对接了”。然后写清楚：怎么运行、做到了什么、没做到什么、需要项目负责人决定什么。同时更新 `backend/WORKLOG.md`。
