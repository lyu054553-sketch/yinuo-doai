# 任务 B：衣诺前端

你负责“衣诺”的全部界面。开工前先完整读完 `docs/开发/00-总体说明与接口约定.md`，后端接口和数据结构都以它为准。

## 你的范围

- **可以改：** `frontend/` 下的所有文件。
- **只读：** 其他目录。`prototype/case2.html` 是早期草图，**只参考交互思路，不复制它的代码和样式。**
- **不运行 git 命令。** 约定需要改动时，写进 `docs/开发/接口变更请求.md`，然后停下来问项目负责人。

## 技术要求

- 用 Vite + React + TypeScript 搭建；不引入大型 UI 组件库。确实需要的小库，先说明理由。
- `frontend/src/api/types.ts` 按约定第 5 节逐字段定义类型；`frontend/src/api/client.ts` 封装约定第 6 节的全部接口。
- 开发时用 Vite 代理，把 `/api` 和 `/files` 转发到 `http://127.0.0.1:8100`。
- **示例数据模式：** `VITE_USE_MOCK=1` 时不连后端，改用 `frontend/src/mocks/` 里的数据。数据要完全符合约定的结构，至少包含案例二的完整会话，回答问题后能按约定的规则升版本、记台账。后端完成 M0 以后，默认改为连真实后端。

## 使用者和场景

使用者是定制业务专员，坐在客户对面，用笔记本电脑操作。界面也会录进 3 分钟的比赛演示视频，所以要做到：
- 字够大，一眼能看清。
- 方案的变化看得见：改动的那一栏要高亮，版本号要醒目。
- 演示时不能出现英文报错和空白页。

请以 1440×900 的桌面屏为主设计，1280 宽也要能正常使用；平板和手机不要求精细适配，但布局不能乱。

## 页面

**1. 新建洽谈**
- 输入客户口述的大文本框。
- 模式切换：“从零生成方案”或“审计已有方案”。选后者时，展开八个字段的输入表单。
- 示例案例选择：调用 `GET /api/samples`，选中后自动填好口述和原方案。案例五标注“测试案例”。
- 提交后等待大模型处理，可能要一到两分钟。期间显示进度提示和当前步骤，比如“正在拆分客户原话…”，可以是示意性的步骤文字。

**2. 洽谈工作台**（核心页面，三栏）
- **左栏：客户原话**
  - 原文逐句加下划线，颜色对应状态；点某一句，右栏对应的字段高亮。
  - 下方上传参考图：调用 `/reference`，显示图片、视觉识别出的各项（标出“疑似”“请人工确认”），以及参考图与口述的冲突。
- **中栏：需求落实审计**
  - 各状态的数量统计。
  - 原话列表，按状态严重程度排序，每条显示强度、对应字段、理由。
  - “需要向客户确认”：每个问题显示背景、为什么问、选项按钮；已回答的问题显示所选的选项。
  - “交给设计师”：设计师事项列表。
  - “不问客户的”：不问清单。
- **右栏：方案，四个页签**
  - **方案**：八栏，每栏显示取值、出处标签（资源 id 和来源案例）、origin；“无出处”要醒目；“客户已确认”显示锁定标记。每栏可以手动修改，填写原因后调用 `PATCH /spec`。
  - **效果图**：提示词（每条可复制）、出图按钮、上传外部效果图做核对、核对结果逐项显示。后端返回 501 时，显示“该功能开发中”。
  - **台账**：按时间倒序。
  - **交接单**：渲染 Markdown，支持一键复制。
- 顶部：会话标题、当前版本号、数据来源标记（“示例数据”或“大模型”）、返回列表。

**3. 洽谈列表**：`GET /api/sessions`，可以点进历史会话。

## 设计要求

- 风格干净、专业，适合业务人员长时间使用。颜色通过 CSS 变量统一管理；状态颜色固定，一种状态一种颜色，状态之外的颜色不能和它们混淆。
- 中文字体优先用系统字体（PingFang SC、Microsoft YaHei），并写好备用字体。
- 加载、空状态、出错都要有设计。出错文字直接用后端返回的 `error`，不显示技术栈错误。
- 键盘可以操作，焦点状态看得见；尊重“减少动态效果”的系统设置。
