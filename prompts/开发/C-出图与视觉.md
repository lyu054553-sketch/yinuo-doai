# 任务 C：衣诺出图与视觉

你负责“衣诺”的三项功能：生成效果图提示词和效果图、解析客户参考图、核对生成的效果图。先完整读完 `docs/开发/00-总体说明与接口约定.md`，尤其是第 5、6、7 节。再读 `vision/README.md` 和 `vision/results/benchmark_v2_report.md`，了解视觉模型测出来的能力边界。

## 你的范围

- **可以改：** `backend/app/media/` 下的所有文件、`backend/app/routers/media.py`、`backend/tests/media/`。
- **只读：** `backend/` 的其他部分，归“后端核心”所有。`schemas.py` 和存储函数直接引用，不要修改；缺什么，写进 `docs/开发/接口变更请求.md`，然后停下来问项目负责人。
- **只读：** `vision/`。视觉推理复用现有的 `vision/server_local.py`（启动时加 `--port 8001`），**不训练，也不改它的代码。**
- **不运行 git 命令。**

后端核心会先搭好骨架，并在 `routers/media.py` 里放占位接口。骨架出来之前，你先在 `media/` 下写独立的模块和测试；骨架出来之后，再把路由接上。

## 功能

**1. 效果图提示词（`media/prompts.py`）**
- 由当前方案版本生成三条提示词：成衣挂拍、面料细节、上身效果。用固定模板拼接，保证相同的方案永远生成相同的提示词，这样才谈得上“参数锁定”。
- 同时生成核对清单 `checks`：从方案文字推出视觉模型能检查的预期值。
  - 领型：从文字映射到视觉词表。例如“青果西装领”对应“翻领”，“低立领”对应“立领”。
  - 纽扣：“无外露纽扣”“无扣开襟”对应“不应看到纽扣”。
  - 纹样：有暗纹，还是无纹样。
  - 衣长、廓形、颜色：照样列出，但标明“需人工确认”。
- 映射表写成独立的数据文件，并配好单元测试。

**2. 生图适配器（`media/image_provider.py`）**
- `IMAGE_PROVIDER=none` 是默认值：不出图，`url` 为空，台账照常记一笔“出图（仅提示词）”。
- `IMAGE_PROVIDER=openai_compatible`：调用兼容接口出图，图片保存到 `backend/storage/files/generated/`，通过 `/files/...` 访问。**第一次真正调用付费接口前，先问项目负责人。**
- 另外支持上传一张外部生成的图片，只做核对。这样即使没有生图接口，演示也能完整走完。

**3. 参考图解析（`media/vision_client.py`、`media/reference.py`）**
- 调用视觉服务的 `POST {VISION_URL}/api/deconstruct`，请求体为 `{"imageDataUrl": "data:image/...;base64,..."}`；返回值的结构见 `vision/schema/deconstruct.schema.json`。
- 按约定第 7 节的冻结策略处理结果：
  - 领型、闭合方式、纽扣、花纹：`used: true`，把握程度最高只能是“疑似”。
  - 衣长、廓形、颜色：`used: false`，界面显示“请人工确认”。
- **冲突检测**（程序规则）：拿识别结果和会话里的原话比对，冲突写进 `reference.conflicts`，并追加一条台账。至少覆盖以下情况：
  - 参考图是立领，客户说领子不能高或要窄：提示“参考图为立领，请确认领高”。
  - 参考图有外露纽扣，客户说不要扣子：提示冲突。
  - 参考图是翻领，客户要求中式立领：提示冲突。
  - 参考图看不到花纹，客户要求暗纹：提示冲突。
  规则写成数据表，方便以后增加。
- 视觉服务连不上时，返回 503 和“视觉服务未启动”。

**4. 效果图核对（`media/check.py`）**
- 用“先解构，再由程序比对”的方式：先让视觉模型独立识别图片，再由程序和 `checks` 逐项比对，给出符合、不符合或看不出。不要把方案规格直接塞给视觉模型去判断，以免它照着规格作答。可以参考 `vision/scripts/verify_compare.py` 的思路。
- 核对结果写进 `GeneratedImage.check`，并追加一条台账。
- 有“不符合”的项、而且配置了生图接口时，自动重画一次，两次结果都要保留。

## 里程碑（每个做完都停下来，向项目负责人汇报）

- **C0：** 提示词和核对清单，以及映射表的单元测试。用案例二、案例六的方案各生成一份，贴进汇报。
- **C1：** 视觉客户端加参考图冲突检测。用 `data/images/c1_garment.jpeg`（立领）配上“脖子短，领子不能太高”的口述，应能报出冲突。贴出真实的输出结果。
- **C2：** 效果图核对。
  - 用 `data/images/c6_garment.jpeg` 对照案例六的方案：交领、无扣，应判为符合。
  - 用 `data/images/c1_garment.jpeg` 对照案例六的方案：领型和纽扣应判为不符合。
  - 照实汇报结果，没达到预期就说明原因。
- **C3：** 接上路由，三个接口用真实后端跑通；生图适配器先保持 `none`。经项目负责人同意后，再接通真实的生图服务。
- **C4（演示素材）：** 写一条生成“高立领、外露扣的新中式外套参考图”的提示词，用来演示参考图与口述冲突，写进 `WORKLOG.md`。不要自己调用付费接口生成这张图。

## 验收标准

- `pytest backend/tests/media` 全部通过；视觉服务没启动时，相关测试自动跳过，并说明原因。
- 同一份方案生成的提示词完全一致。
- 参考图解析和核对的结果，只用冻结策略允许的字段做判断；不允许判断的字段一律标为“看不出”或“请人工确认”。
- 所有返回都符合约定第 5 节的结构。

## 汇报方式

用中文写，开头一句话说结论；贴出真实的输入和输出，写清楚没做到的部分。同时更新 `backend/app/media/WORKLOG.md`。
