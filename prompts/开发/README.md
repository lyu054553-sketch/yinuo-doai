# 多个 AI 并行开发：怎么用这些提示词

## 文件

| 文件 | 交给谁 |
|---|---|
| `docs/开发/00-总体说明与接口约定.md` | 所有 AI 都要先读；只有你能改 |
| `A-后端核心.md` | AI 甲 |
| `B-前端.md` | AI 乙 |
| `C-出图与视觉.md` | AI 丙 |
| `D-评测.md` | AI 丁，后端出了 M0 之后再启动 |

每个 AI 开工时这样说：“请读 `prompts/开发/X-xxx.md` 并执行，从第一个里程碑开始。”

## 启动顺序

| 时间 | 甲：后端核心 | 乙：前端 | 丙：出图与视觉 | 丁：评测 |
|---|---|---|---|---|
| 11/18 晚 | M0 骨架与示例模式 | F0 用示例数据做界面 | C0 提示词和核对清单 | 未启动 |
| 11/19 | M1 大模型解构与审计 | F1 接真实后端，F2 | C1 参考图冲突 | D0 评测脚手架 |
| 11/20 | M2 从零生成方案 | F3 参考图和效果图区域 | C2 核对，C3 接路由 | D1 造注入问题集，交你审核 |
| 11/21 | M3 稳健性，修评测发现的问题 | F4 打磨演示效果 | 接真实生图（需你同意） | D2 正式评测 |
| 11/22 | 修问题 | 修问题 | C4 演示素材 | 你宣布冻结后跑 D3，再做 D4 |
| 11/23 | 部署、演练 | 部署、演练 | — | — |
| 11/24 | 录视频、写文档 | | | |

**甲的 M0 是所有人的依赖，一定要最先完成。**乙和丙在甲完成前可以先做各自独立的部分，不受影响。

## 你每天要做的

1. **看每个 AI 的汇报。**汇报开头第一句是结论，先看这一句。
2. **处理接口变更请求。**看 `docs/开发/接口变更请求.md`；同意的话，修改约定文件，再通知所有 AI 重新读一遍。
3. **在每个里程碑完成时提交一次 git。**AI 们不会提交，版本由你保存。如果拿不准怎么提交，可以让其中一个 AI 只做这一件事：“只执行 git add 和 git commit，提交信息写某某里程碑，不改任何文件”。
4. **11/22 宣布冻结**：从这天起，只修问题，不加新功能。之后才让丁跑留出集。

## 怎么在本机跑起来

```bash
# 视觉服务（丙需要；端口 8001）
.venv-vision/bin/python vision/server_local.py --port 8001
```

```bash
# 后端（端口 8100），启动命令以甲在 backend/WORKLOG.md 里写的为准
cd backend && uvicorn app.main:app --port 8100 --reload
```

```bash
# 前端（端口 5173）
cd frontend && npm run dev
```

## 要你做决定的事

- **大模型用哪家：**默认是本机 Ollama，免费但可能较慢。换云端模型只要改 `backend/.env`，但会产生费用。
- **生图用哪家：**默认不出图。接入付费生图服务前，丙会先问你。
- **作品怎么交：**交可访问的链接，还是只交视频和代码，等对接人回复。如果要交链接，11/23 部署之前要确认好。
