# 任务：为「衣诺」微调一个海派定制服装视觉模型

## 背景

我们在参加 2026 DOAI 全球创客大会 FDE 赛道，赛题是上服集团的「海派定制服饰 AI 需求解构与可视化 Agent」，**11 月 25 日截止提交**。项目根目录下：

- `DOAI参赛产品选题调研.md`：产品方案。先读“海派定制专属视觉模型”一节。
- `data/README.md`：数据说明和使用规则，必须先读。
- `data/images.json`：上服 15 张真实图片的标注；图片在 `data/images/`。
- `data/cases.json`、`data/resources.json`：6 个案例和资源库，用来设计规格字段和生成数据。
- `prototype/case2.html`：已有的案例二样稿，最后要把模型接到这里。

## 目标

在一个开源视觉语言模型（首选 Qwen2.5-VL 7B，或平台上同系列可微调的版本）上做 LoRA 微调。同一个模型完成两个任务：

1. **看图解构**：输入一张服装图，输出上服格式的规格 JSON。每个字段都附把握程度：`确定`、`疑似` 或 `看不出`。
2. **效果图核对**：输入一张服装图和一份方案规格，逐项输出 `符合`、`不符合` 或 `看不出`，并说明理由。

字段和可选值以 `data/images.json` 里的 `label_values` 为准：领型、闭合方式、纽扣是否可见、衣长、廓形，另有纹样、颜色两个自由文本字段。

模型不做以下判断，遇到时一律输出 `看不出`：尺寸数值、面料成分、穿着舒适度、能否确定是梅花等具体纹样。

## 成功标准（团队自定目标，不是已知结果）

- 输出 JSON 格式合法率 100%。
- 在上服真实图片上，领型识别准确率明显高于未微调的底座模型。
- “确定但错误”率（模型标为“确定”的字段里，答错的比例）接近 0。
- 核对任务能抓出大部分故意写错的规格项。
- 只要和底座模型、通用视觉大模型相比没有一项明显更好，就判定微调失败。失败也是有效结论，照实报告即可。

## 硬性规则

1. **上服的 15 张真实图片只能做测试。** 不得出现在训练数据、提示词示例或 few-shot 里。
2. **不编造结果。** 每个数字都必须来自真实运行，并保存原始输出。脚本跑失败就如实报告，不要估算一个数补上。
3. **以下操作要先停下来问我：** 创建账号、充值或付费、上传任何数据到外部平台（包括把上服图片发给第三方 API）、启动训练任务、任何预计花费超过 50 元的批量调用。提问时说明要做什么、调用多少次、预计花费多少。
4. **API Key 只从环境变量读取**，不写进代码、文件或对话。需要哪个 Key，告诉我变量名，我来设置。
5. **只用自己生成的图片。** 公开图片只有在许可明确允许时才能用，并在数据说明里记录来源和许可；不得爬取网站图片。
6. **每个阶段结束都停下来**，交给我一份简短报告（做了什么、结果、下一步、需要我决定什么），等我确认再继续。

## 文件组织

所有新文件放在 `vision/` 目录下：

```
vision/
  schema/      输出格式定义和两个任务的指令模板
  scripts/     数据生成、格式转换、评测脚本
  data/        生成的训练和验证数据（不放上服图片）
  results/     各阶段的原始输出和报告
  README.md    说明如何复现每一步
```

## 分阶段步骤

### 阶段 0：复核测试标注、调研平台（目标 11/18）

1. `data/images.json` 的标注是 AI 目测的，还没经过人工复核。做一个 HTML 复核页：每张图旁边列出标注，我逐项确认或修改，确认结果另存为 `vision/results/gold_labels.json`。
2. 调研能微调 Qwen2.5-VL（或同类开源视觉模型）的方案，至少比较 3 个，包括国内云平台的一键微调，以及租用 GPU 自己用 LLaMA-Factory 或 ms-swift 训练。对比项：支持的模型版本、是否支持 LoRA、数据格式、预计费用、训练耗时、训练后怎样调用，以及不需要写代码时我要做哪些操作。
3. **停下**，给出推荐方案，等我选定并开好账号。

### 阶段 1：定格式、测基线（目标 11/19）

1. 在 `vision/schema/` 写出两个任务的输出 JSON Schema 和指令模板，指令全部用中文。
2. 写 `vision/scripts/eval.py`：
   - 看图解构：对每张测试图，统计每个字段的准确率、格式合法率、“确定但错误”率。金标准为“看不出”的字段，单独统计模型有没有老实回答“看不出”。
   - 效果图核对：用上服真实图片加金标准规格，组成“全部正确”的样本；再对每张图随机改错 1–2 个规格项，组成“有错”的样本。统计改错项被判为“不符合”的比例，以及正确项被误判为“不符合”的比例。
   - 原始输出逐条存进 `vision/results/`。
3. 用这个脚本测两个模型：未微调的底座模型和一个通用视觉大模型。**调用外部 API 前先问我。**
4. **停下**，报告基线结果，并指出底座模型主要错在哪些字段。如果底座模型已经足够好，直接建议放弃微调。

### 阶段 2：造训练数据（目标 11/20）

1. `vision/scripts/gen_specs.py`：按字段可选值组合抽样，生成规格清单。要求：
   - 各领型数量大致均衡。
   - 视角混合：正面挂拍、背面挂拍、上身全身、局部特写。
   - 风格贴近上服案例，以新中式外套为主，少量连衣裙。
   - 从 `data/resources.json` 取面料和纹样描述。
2. 把每份规格转成生图提示词，规格就是这张图的标签。
3. **先试跑 20 张**，做成对照页给我看图和标签是否一致。确认后再批量生成，目标 300–500 张。**批量前先报调用次数和费用。**
4. 用强视觉模型检查每张生成图是否真的符合规格，标出不一致的图，抽 10% 做成复核页给我看。剔除画错的图，或按图片实际内容改标签。
5. 制作“看不出”样本：对部分图片程序裁剪，比如只留背面、只留局部。被裁掉的字段，标签改为“看不出”。
6. 制作核对任务样本：图片配规格，其中约一半随机改错 1–2 项，标签为对应项“不符合”。
7. 按选定平台要求的格式输出训练集和验证集（验证集也只用生成图），并写数据说明：数量、各类分布、来源、剔除了多少张。
8. **停下**，报告数据情况，等我确认后再上传。

### 阶段 3：微调（目标 11/21）

1. 给出训练配置：LoRA 参数、训练轮数、学习率。先用平台推荐的默认值，并说明理由。
2. **经我同意后**再上传数据、启动训练；需要在网页上操作的步骤，写清楚让我照着做。
3. 训练过程中记录验证集指标；训练完拿到可调用的模型地址。

### 阶段 4：对比评测与去留决定（11/22）

1. 用同一个 `eval.py`，在同一批真实测试图上测微调后的模型。
2. 写 `vision/results/finetune_report.md`，内容包括：
   - 三个模型（底座、通用大模型、微调后）的对比表。
   - 每个字段的准确率、“确定但错误”率、核对任务的抓错率和误报率。
   - 典型对错案例（附图片文件名）。
   - 明确写出局限：测试集只有 15 张图，错 1 张，准确率就变化约 7 个百分点；训练数据全是生成图。
3. 给出结论：按成功标准判断微调成功还是失败。不论哪种结果，都写清楚对外该怎么说：
   - 成功：“基于 Qwen2.5-VL 微调的海派定制视觉模型”。
   - 失败：不提微调，改用底座模型加提示词。
   - 任何情况下都不写“自研大模型”。

### 阶段 5：接入样稿（11/23，仅在我确认后）

在 `prototype/` 中增加两个功能：

- 上传参考图后，调用看图解构，把结果和客户口述的规格逐项比对，列出冲突（例如参考图是高立领，客户说领子不能高）。
- 效果图生成后调用核对，显示每一项的核对结果。

API Key 不能写进前端页面。如果需要后端，先说明方案，等我确认。

## 汇报方式

用中文、尽量少用术语，让不写代码的人也能看懂。每次汇报开头先用一句话说清楚结论，比如“基线测完了，底座模型领型错了 6/15，建议继续微调”，然后再写细节。
